Предмет: «Тестирование ПО». Объект тестирования: веб-приложение «ChessMaster» (курсы по шахматам).

Файл собран из всего, что обсуждалось в чате. Где позднее решение заменило раннее, указано итоговое значение.

## Часть 0. Изменения бизнес-логики (итоговые правила)

### 0.1. Что такое курс

Курс это **групповое занятие**: онлайн-группа или очное занятие. У него ограниченное число мест, дата начала и цена. Поэтому ручное решение преподавателя по заявке оправдано: он формирует группу. Отклонение заявки допустимо, но требует причины.

### 0.2. Параметры курса

| Параметр | Правило |
| --- | --- |
| Название | 3–100 символов (значение из ЛР2) |
| Краткое описание | 10–300 символов (значение из ЛР2) |
| Тематика, уровень | значения из справочников |
| Формат | «Очно» или «Онлайн-группа» |
| Вместимость | целое число от 1 до 20 |
| Дата начала | сегодня или позже |
| Цена | от 100,00 до 100 000,00 руб., два знака после запятой (значение из ЛР2; 0 недопустим) |
| Место проведения | обязательно для очного формата, для онлайн-группы не требуется |

### 0.3. Жизненный цикл заявки

`На рассмотрении → Одобрена → Оплачена`, а также `Отклонена`, `Отменена`, `Истекла`.

| Переход | Условие |
| --- | --- |
| Создана → «На рассмотрении» | курс ещё не начался, есть свободные места, у ученика нет активной заявки на этот курс |
| «На рассмотрении» → «Одобрена» | решение преподавателя курса; есть свободное место (оно резервируется) |
| «На рассмотрении» → «Отклонена» | решение преподавателя; причина обязательна, 5–200 символов, её видит ученик |
| «На рассмотрении» → «Отменена» | ученик отменяет до решения преподавателя |
| «Одобрена» → «Оплачена» | успешная оплата в течение 3 дней |
| «Одобрена» → «Истекла» | оплата не поступила за 3 дня, место освобождается |

- Решение преподавателя принимается один раз, повторно сменить статус нельзя.
- Активной считается заявка в статусах «На рассмотрении», «Одобрена»; в статусе «Оплачена» ученик уже записан, новая заявка на этот курс не нужна и недоступна.
- После «Отклонена», «Отменена» и «Истекла» можно подать новую заявку.
- Преподаватель видит и обрабатывает заявки только на свои курсы.

### 0.4. Места

- Место резервируется при одобрении заявки.
- Одобрить заявку при нулевом числе свободных мест нельзя («Нет свободных мест»).
- Место освобождается, когда заявка становится «Истекла» или ученик удалён из системы.
- Вместимость нельзя уменьшить ниже числа одобренных и оплаченных заявок.
- На карточке и странице курса показывается «Свободно мест: X из Y»; при нуле кнопка заявки недоступна («Мест нет»).

### 0.5. Удаление и архивирование курса (итоговое решение)

Купленный курс у ученика отобрать нельзя. Поэтому:

| Ситуация | Что можно |
| --- | --- |
| Заявок нет | Удалить |
| Только «Отклонена», «Отменена», «Истекла» | Удалить |
| Есть «На рассмотрении» | Удалить после подтверждения; эти заявки автоматически становятся «Отменена» |
| Есть «Одобрена» или «Оплачена» | Удалить нельзя, выводится сообщение и предлагается архивирование |
| Любой свой курс | Архивировать |
| Чужой курс | Нельзя ни удалять, ни архивировать |

Архивный курс: не отображается в каталоге, новые заявки на него невозможны, у оплативших учеников остаётся в «Мои курсы».

### 0.6. Личный кабинет ученика

- В «Мои курсы» отображаются только курсы с заявкой «Оплачена».
- Одобренная, но не оплаченная заявка отображается со статусом «Ожидает оплаты», сроком оплаты и кнопкой оплаты.
- Отдельно отображается список заявок со статусами; для «Отклонена» показана причина.

### 0.7. Администратор

- Редактирует имя, фамилию и роль пользователей, удаляет пользователей.
- Не может удалить себя (чтобы система не осталась без администраторов).
- При удалении ученика его активные заявки отменяются, зарезервированные места освобождаются.

Необязательные правила (добавлять в требования только если нужны соответствующие кейсы):
- смена роли преподавателя на ученика недопустима, пока у него есть курс с одобренными или оплаченными заявками;
- администратор не может сменить роль самому себе.

### 0.8. Чего в проекте нет (в ЛР3 отмечается знаком «−»)

Возврат оплаты, лист ожидания, исключение ученика с курса преподавателем, уведомления по email, прохождение уроков с прогрессом сверх уже описанного.

### 0.9. Несоответствия между лабами, которые нужно выровнять

| Что | Где расходится | Как выровнять |
| --- | --- | --- |
| Длина названия курса | ЛР2: 3–100, ЛР3: 2–100 | 3–100 |
| Длина описания курса | ЛР2: 10–300, ЛР3: 2–200 | 10–300 |
| Цена | ЛР2: 100–100 000, в предложенной ЛР1 было 0–100 000 | 100,00–100 000,00 |
| Статусы заявки | ЛР3: «Принято», «Отказано»; остальные лабы: «Одобрена», «Отклонена» | «Одобрена», «Отклонена» |
| Кнопка записи | ЛР2: «Записаться»; ЛР1, ЛР3, ЛР4: «Оставить заявку» | «Оставить заявку» |
| «Мои курсы» | ЛР3 и ЛР1 (2.3): по одобренным заявкам | только оплаченные |
| Курс в базовых данных | ЛР4: «Дебют для начинающих»; ЛР2: «Итальянская партия для начинающих» | один из двух во всех лабах |
| Поля формы курса | ЛР3: нет «Уровень» и «Цена» | добавить |

## Часть 4. ЛР4: Тест-кейсы

### 4.1. Изменить существующие кейсы

- **ID 3 (оставление заявки):** в предусловие добавить «у курса есть свободные места».
- **ID 4 (создание курса):** в шаги добавить формат «Онлайн-группа», вместимость 10, дату начала в будущем и цену 1500,00. В ОР добавить: на карточке отображается «Свободно мест: 10 из 10».
- **ID 5 (обработка заявки и оплата):** в ОР добавить, что до оплаты курс не отображается в «Мои курсы», а место зарезервировано; после оплаты статус «Оплачена».

### 4.2. Новые кейсы

Общие условия те же, что в ЛР4: учётные записи pupil@mail.ru, teacher@mail.ru, admin@chessmaster.ru, пароль Qwerty12. Окружение у всех: Google Chrome 120 и выше, Windows 10/11. ID присвойте по своей нумерации.

#### Заявки и места

**Заявка на курс без свободных мест**
- Предусловие: вход как ученик; у курса вместимость 1, место занято оплаченной заявкой.
- Шаги: открыть страницу курса.
- ОР: кнопка «Оставить заявку» недоступна, отображается «Мест нет».
- Требование: ЛР1, раздел 2.2: «Кнопка «Оставить заявку»».

**Одобрение заявки при нехватке мест**
- Предусловие: вход как преподаватель; вместимость курса 1, две заявки «На рассмотрении».
- Шаги: принять первую заявку, затем вторую.
- ОР: первая получает «Одобрена», при второй отображается «Нет свободных мест», статус второй не меняется.
- Требование: ЛР1, раздел 2.2: «Обработка заявки».

**Отклонение заявки с причиной**
- Предусловие: вход как преподаватель; есть заявка «На рассмотрении».
- Шаги: нажать «Отклонить», ввести причину «Группа уже сформирована», подтвердить; войти как ученик.
- ОР: статус «Отклонена», ученик видит причину и может подать новую заявку.

**Отклонение заявки без причины**
- Шаги: нажать «Отклонить», оставить поле пустым (затем ввести 4 символа), подтвердить.
- ОР: ошибка валидации, статус остаётся «На рассмотрении».

**Отмена заявки учеником**
- Шаги: создать заявку, нажать «Отменить заявку»; затем проверить заявку в статусе «Одобрена».
- ОР: статус «Отменена», для одобренной заявки кнопки отмены нет.

**Истечение срока оплаты**
- Предусловие: одобренная заявка, дата одобрения сдвинута на 3 дня назад (через БД или тестовый режим).
- Шаги: войти как ученик, открыть заявки.
- ОР: статус «Истекла», оплата недоступна, место освобождено (свободных мест на 1 больше).
- Требование: ЛР1, раздел 2.2: «Срок оплаты».

#### Управление курсами

**Создание курса с некорректной вместимостью**
- Шаги: заполнить форму, указать вместимость 21 (затем 0), нажать «Создать».
- ОР: ошибка, курс не создан.

**Удаление курса без заявок**
- Предусловие: вход как teacher@mail.ru; у преподавателя есть курс «Тактика и комбинации», заявок на него нет.
- Шаги: открыть «Управление курсами», у курса нажать «Удалить», в диалоге нажать «Да», открыть каталог.
- ОР: курс исчез из раздела «Управление курсами» и из каталога.
- Требование: ЛР1, раздел 2.3: «Управление курсами».

**Удаление курса с заявкой «На рассмотрении»**
- Предусловие: на курс «Тактика и комбинации» есть заявка pupil@mail.ru «На рассмотрении».
- Шаги: у курса нажать «Удалить» и подтвердить; выйти и войти как pupil@mail.ru; открыть список заявок.
- ОР: курс удалён; у ученика заявка в статусе «Отменена», в «Мои курсы» курса нет.

**Удаление курса с одобренной или оплаченной заявкой**
- Предусловие: на курс «Дебют для начинающих» есть заявка «Одобрена» (повторить для «Оплачена»).
- Шаги: в «Управлении курсами» нажать «Удалить» у этого курса.
- ОР: удаление не выполнено, отображается сообщение, что курс с активными заявками удалить нельзя, предложено архивирование. Курс остаётся в списке, статус заявки не меняется.

**Отказ от удаления и доступ к чужому курсу**
- Шаги: нажать «Удалить» у своего курса и в диалоге выбрать «Отмена»; войти как другой преподаватель и открыть удаление чужого курса по прямой ссылке.
- ОР: после отмены курс остаётся в списке; чужой курс удалить нельзя, доступ запрещён.

**Архивирование курса с оплатившим учеником**
- Предусловие: вход как teacher@mail.ru; на курс «Дебют для начинающих» есть заявка pupil@mail.ru «Оплачена».
- Шаги: в «Управлении курсами» у курса нажать «Архивировать» и подтвердить; открыть каталог; войти как pupil@mail.ru и открыть «Мои курсы»; войти как другой ученик и открыть страницу курса по прямой ссылке.
- ОР: курс исчез из каталога; у pupil@mail.ru он остался в «Мои курсы»; новому ученику кнопка «Оставить заявку» недоступна.
- Требование: ЛР1, раздел 2.3: «Управление курсами».

#### Управление пользователями (администратор)

Общее предусловие: вход как admin@chessmaster.ru / Qwerty12; существует тестовый ученик pupil2@mail.ru / Qwerty12 («Пётр Сидоров»). После каждого кейса вернуть исходные данные.
Требование для всех: ЛР1, раздел 2.3: «Управление пользователями».

**Редактирование имени и фамилии пользователя**
- Шаги: в «Управление пользователями» открыть редактирование Петра Сидорова, заменить имя на «Павел», нажать «Сохранить», войти как pupil2@mail.ru и посмотреть шапку.
- ОР: в списке отображается «Павел Сидоров», в шапке у ученика то же имя.

**Редактирование имени некорректными данными**
- Шаги: открыть редактирование, ввести имя «Пётр2» (затем «Я» и пустую строку), нажать «Сохранить».
- ОР: ошибка валидации, данные не сохранены. Правила те же, что при регистрации: 2–30 символов, только буквы, пробел и дефис.

**Смена роли ученика на преподавателя**
- Шаги: открыть редактирование, выбрать роль «Преподаватель», сохранить, войти как pupil2@mail.ru и открыть раздел «Управление курсами».
- ОР: в списке роль «Преподаватель», раздел «Управление курсами» доступен, разделы ученика недоступны.
- Постусловие: вернуть роль «Ученик».

**Доступ к управлению пользователями без роли администратора** (можно не добавлять, если покрыто кейсом 6)
- Шаги: войти как teacher@mail.ru и открыть «Управление пользователями» по прямой ссылке.
- ОР: переход блокируется.

**Удаление ученика с активной заявкой**
- Предусловие: у pupil2@mail.ru есть заявка «На рассмотрении» на курс «Дебют для начинающих».
- Шаги: в «Управление пользователями» у pupil2@mail.ru нажать «Удалить» и подтвердить; войти как teacher@mail.ru и открыть «Управление заявками»; попробовать войти как pupil2@mail.ru / Qwerty12.
- ОР: пользователь исчез из списка; его заявка отсутствует или в статусе «Отменена», место на курсе свободно; вход невозможен, отображается «Неверный email или пароль».

**Удаление администратором самого себя**
- Шаги: в «Управление пользователями» у своей записи нажать «Удалить» (если кнопка есть, подтвердить).
- ОР: удаление не выполнено, сообщение, что нельзя удалить свою учётную запись (либо кнопка недоступна); администратор остаётся авторизованным.

#### Необязательные кейсы (только если добавлены правила из п. 0.7)

- Смена роли преподавателя на ученика при наличии курса с одобренными или оплаченными заявками: отказ с сообщением; без таких заявок смена проходит.
- Администратор меняет роль самому себе: отказ.

### 4.3. Сколько получится кейсов

Базовые 6 + заявки и места 6 + курсы 6 + пользователи 6 дают около 24–30 кейсов. Если нужно ближе к 25, оставьте по три кейса на удаление курса и на пользователей: для курсов «без заявок», «с одобренной или оплаченной» и «отказ от удаления», для пользователей «редактирование», «некорректные данные» и «смена роли».
